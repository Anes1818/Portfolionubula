# معاينة المتجر أولًا — 2 نوفمبر 2026

هذا المسار يحل محل «الذهاب إلى صفحة المنتجات بعد التسجيل» كمدخل الإعداد الافتراضي. صفحات إدارة المنتجات والإعدادات السابقة تبقى متاحة.

## مسار صاحب المحل

1. يكتب اسم المحل ويختار طبيعي / ساتان / النوعين. العنوان والعملة والبلد والمنطقة الزمنية داخل تفاصيل اختيارية، مع عنوان مقترح صالح للأسماء غير اللاتينية أيضًا.
2. يفتح متجره الخاص باسمه مباشرة. بعد ظهوره، دعوة قابلة للإغلاق: «ابنِ أول باقة». يمكنه استكشاف الصفحة أو تحرير تصميمها قبل المتابعة.
3. يفتح البيلدر الفعلي. يتيح الاستكشاف لصاحب المحل قبل إدخال الأسعار؛ لا يوسع مكتبة الزبون أو يتجاوز فحص الخادم. تبقى ساتان دون Classic، ومحركات الرسم الأصلية محفوظة.
4. «التالي: الصورة والأسعار» يحفظ الوصفة أولًا، ثم يطلب الاسم وصورة الباقة الحقيقية وأسعار العناصر المستخدمة فقط. يمكن اختيار صورة البيلدر مع تسميتها بوضوح كمعاينة، أو إكمال الصورة لاحقًا.
5. اختيار «إبقاء العناصر غير المسعرة مخفية» ظاهر في نموذج الحفظ، ويمكن تغييره. لا تُنسخ أسعار نموذجية ولا تصبح الأسعار المفقودة صفرًا. التغيير في المسودة؛ لا يغيّر نسخة المتجر المنشورة تلقائيًا.
6. تعود الباقة إلى متجره بصورتها ووصفة التخصيص نفسها، ثم يضيف رقم استقبال طلبات WhatsApp/SMS في نموذج صغير. تبقى إعدادات Square والتوصيل المتقدمة منفصلة.
7. بعد رؤية النتيجة: غير المفعّل يرى السعر الحقيقي $29 USD لكل 30 يومًا ومسار طلب التفعيل اليدوي. المفعّل يرى النشر مباشرة عندما تجتاز محتوياته الفحص؛ لا يُطلب دفع ثانٍ. فتح الطلبات يتطلب نشرًا فعليًا، ومعاينة صاحب المحل تبقى غير قابلة لإرسال طلب.

عرض القيمة يعتمد على رؤية المحل لعمله وتجربة تخصيصه. لا توجد أرقام مبيعات أو استعجال أو ندرة مصطنعة، ولا اشتراك أو تحصيل عند حفظ المعاينة. تأثير المسار على التحويل لم يُقَس بعد.

## إصلاحات مرتبطة

- زر متابعة الصفحة الرئيسية يفتح المتجر بدل صفحة الفوترة عندما ينقص أول تصميم أو أسعاره.
- الرابط القديم `/dashboard/billing?setup=1` يعيد المحل المفعّل إلى معاينته. تبقى صفحة الخطة العادية متاحة لإدارة الوصول.
- مقارنة النشر تستخدم `published.sourceVersion`، لأن `published.version` عدّاد نشر مستقل. لا يظهر طلب نشر التغييرات نفسها باستمرار.
- بطاقة الدفع تفرّق بين توقف checkout على مستوى المنصة وعدم توصيل Square؛ لا تدّعي أن حساب التاجر غير مربوط عندما لم تُقرأ حالته.
- الأقسام الفارغة للمنتجات والباقات لا تظهر في المعاينة أو واجهة الزبائن. تبقى ظاهرة في المحرر لإضافة المحتوى.

## التحقق وحدود النسخة

- 106 اختبارات خادم/سياسة ناجحة، بما فيها إعداد باقة طبيعي وساتان دون تسعير المكتبة، رفض النشر غير المسعر، وحفظ عزل العملاء والأسعار.
- تجربة متصفح كاملة: اسم ← متجر خاص ← بيلدر ساتان قبل الأسعار ← حفظ وقفة/استكمال دون تكرار البطاقة ← صورة وأسعار ← رقم اتصال ← عرض تفعيل صريح ← نشر للمحل المفعّل ← Order يفتح المراجعة وCustomise يفتح التصميم نفسه. تحقق من الاسم العربي وعدم كشف المعاينة لزائر غير مالك.
- اختبارات المحرر والمحلات القديمة، الإعداد بالمنتج الجاهز، والتفعيل الإداري ناجحة. خدمات الهوية والمدفوعات في هذه الاختبارات محلية ومحاكاة، ولا رسائل أو أموال حقيقية.
- البيلدر الأصلي بقي بـ35 ملف runtime دون تعديل، و225 أصلًا بصريًا. التعديل في محوّل المنصة والواجهة فقط.
- تفعيل Production العام للدفع يبقى متوقفًا حتى قبول أول محل حقيقي. هذا التغيير لا يسجل اشتراكًا مدفوعًا أو يُجري ربط Square أو تحصيلًا بالنيابة عن أحد.
